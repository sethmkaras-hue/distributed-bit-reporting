# Hardware integration and production gates

The delivered simulation is executable. Hardware mode deliberately rejects unsupported controls and reports unavailable measurements. It is not a commissioned Kria deployment.

Implement the Provider protocol for actual PS sensors, PL telemetry, processing process supervision, reset, signed artifact staging and PL programming. Do not substitute guessed registers, sysfs paths or invented FPGA diagnostics. Split hardware adapter execution into validated prepare/execute/verify stages. Verify software and PL artifact signatures against configured trust roots before applying. The mock accepts only explicit `sim-*` artifact IDs. Hardware controls currently raise NotImplementedError, including start/stop.

Integrate linuxptp/PHC status through a provider implementing Quality. Confirm Ethernet PTP hardware timestamp support, PHC/PS clock relationships, grandmaster identity, offset and uncertainty. The CPU is not assumed to be grandmaster. Prove <=100 μs on the final PL Ethernet implementation with actual instruments and PTP configuration. Simulation quality labels do not establish timing accuracy.

Validate PS independence from PL, PS sensor accessibility during PL reprogramming, Ethernet disappearance/reappearance and replay. Program operations must provide a verified post-operation artifact identity. Reset must demonstrate a new boot identity and enter quarantine. Boot image download, initial Ethernet bootstrap and failed-image recovery belong to external provisioning systems.

Run one agent process per SOM with its fixed inventory identity and mTLS certificate. Certificates require a common name equal to the stable SOM ID, CPU common name `cpu` (reserved and rejected as a SOM ID), and SANs matching configured gRPC endpoints. Use a dedicated CA and unique private keys. Certificate rotation, revocation and credential provisioning are deployment responsibilities. Only trusted, non-Byzantine nodes may share this CA. CPU bearer identities map to viewer/operator/admin; terminate HTTPS at a configured reverse proxy. The production CLI requires TLS settings and rejects unconfigured operator authentication. Never expose the unauthenticated loopback simulator via a public reverse proxy.

Before commissioning: validate monotonic clock rate/suspend assumptions of the lease protocol, CPU-to-peer latency below the configured request bound, mutually authenticated identity checks, target RSS and buffer accounting at 500 BITs/node, PetaLinux Python/gRPC dependency availability for aarch64, PostgreSQL durability and recovery, disk-full handling, long-running 400-node load and browser visibility under target network conditions. Voters lose grants at reboot and must observe the full startup blackout. Configured voting membership is immutable while running; use a coordinated stop/change/restart procedure. Do not run duplicate live instances with the same SOM identity.

Provider reads must remain short/nonblocking or use a separate acquisition cache; slow sensor I/O must not block the agent event loop. Complete and test real processing supervision before commissioning: the simulation enforces processing state logically, while hardware start/stop and stop-on-quarantine hooks still require the actual provider implementation. Verify register/counter widths and lossless browser presentation for integers beyond JavaScript safe-integer range during hardware integration.
